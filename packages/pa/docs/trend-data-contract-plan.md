# Trend Report 接口计划

本文件只确定后续接口方向，不声称 Trend 已实现容量、配置、性能联合分析。
已有历史容量趋势 Skill 不因此被替换。

## 三个 Skill 的边界

- SAM：产出一次 ASUP 配置/容量快照及来源证据。
- PA：产出一次性能采样窗口的指标、覆盖、来源证据。
- Trend：只读历史结果，按身份、时点和口径做变化分析；不嵌入或改写两套解析器。

先使用现有 PA `report_model.json` 与运行证据，并为 SAM 定义稳定的导出适配器。
不要依赖 Excel 单元格坐标作为长期接口，也不为未来趋势提前改坏已验收表格。
这些中间结果属于客户私有数据，不入 GitHub。

## 建议的版本化数据约定

| 类别 | 后续接口需要记录 |
| --- | --- |
| 来源 | 报告类型、软件版本、schema/metric 版本、源 SHA、批次 ID、校验状态 |
| 身份 | 本地 Site 标识、cluster UUID、node UUID、SVM/volume UUID、FlexGroup 身份与成员关系 |
| 时间 | 实际快照时点或 PA 起止时间、时区、原生粒度、有效分钟与覆盖率 |
| 数值 | counter、数值、单位、统计层级、聚合方式，必要时保留分子/分母 |
| 状态 | 明确零、无样本、无 counter、不适用、身份无法匹配、校准待确认分别记录 |
| 配置 | 节点型号/ONTAP、端口角色和速度、卷/聚合归属等与指标有关的配置时点 |

上述为设计清单，不是已落地的通用 schema。后续按实际 SAM/PA 导出结构和
匿名测试确定 `schema_version`，再写转换器；不提前要求用户收集新材料。

## 比较规则

同名卷跨 SVM/集群不合并；迁移、重建和 UUID 变化需要同窗 ASUP 映射证据。
FlexGroup 成员数变化单列结构变更，不直接当负载突变。
快照容量与时间窗口平均性能不能作为同类量相加。
采样窗口和负载时段不兼容时标记为不可直接比较。

配置趋势先报告增加、减少、型号/版本/归属变化，再关联性能变化；
关联不代表因果。单位/聚合/指标版本变化需要显式迁移或分段展示。
季度和年度结论应显示实际收到批次与覆盖，而非伪造连续观测。
预测应在历史样本数量和质量足够后单独验收，不能先承诺准确度。
