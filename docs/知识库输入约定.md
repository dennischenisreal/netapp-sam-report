# 自己的知识库应如何准备？

此文根据包内既有解析器整理，不修改读取规则。知识库不在分发包中提供；禁止拿虚构固件、维保或Case数据用于真实报告。所有目录都相对于setup显式选择的Knowledge根目录。

| 子目录 | 文件和主要结构 | 注意事项 |
|---|---|---|
| `ONTAP EOS date` | 一个当前有效的 `.xlsx`；第2行为表头，含 `Version`、`End of Limited Support` | 第1行为说明；版本前缀用于匹配。 |
| `Platform EOS date` | 一个当前有效的 `.xlsx`；第1行为表头，含 `设备型号`、`EOS日期` | 模型及日期由原解析规则匹配。 |
| `MA date` | 一个 `.xlsx`；按位置读取，不把首行当表头：A列备注、B列序列号、C列开始日期、D列到期日期、E列服务级别 | 序列号需与自己的ASUP一致；不能复制别人的维保数据。 |
| `BMC firmware` | `.xlsx`第一张表，第3行起A列固件主版本、B列最新版本 | 前两行为说明/表头；主版本格式例如 `BMC 15.x`，具体版本必须来自自己确认的来源，不填虚构数值。 |
| `JV Case 数据源` | 目录需存在；文件前缀为 `Case查询-YYYY年` 且后缀 `.xlsx`，首行为列名 | 原代码按运行时当前年度及上一年度查找，不是任意报告月份都能匹配所有历史Case。无记录可为空，但不能把目录不存在当作正常无Case。 |

Case列名包括：`Case ID`、`Case创建时间`、`四级产品树`、`主机编号`、`故障二级分类`、`故障三级分类`、`故障四级分类`、`问题描述`、`客户姓名`、`企业名称`、`是否有上门单`。其中主机编号用于与设备序列号匹配；实际报表逻辑以`legacy-case/parse_c1_case.py`为准。

不要在同一个“选单文件”的知识库子目录堆放多个旧版Excel：现有适配器会选择找到的文件，不承诺自动挑选最新业务内容。本分发工作没有改变这种行为。

固件知识库缺失可能产生告警或空版本对照；Controller所需Excel缺失或格式错误可能使模块失败。doctor主要检查运行依赖、清单和部署镜像，不替代知识库的业务完整性核验。

需要核实具体匹配方式时，setup后的`runtime/src/legacy-controller-firmware/parse_asup_logs_final.py`、`generate_all_final.py`与`runtime/src/legacy-case/parse_c1_case.py`保留原逻辑。本指南不承诺其他形态的Excel会被自动修复或转换。
