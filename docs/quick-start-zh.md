# 中文使用指南

## 1. 适用场景

存储管理员定期收集 ONTAP ASUP 日志，希望把分散的配置和容量数据整理为客户可阅读的 Excel 巡检报告。主 Skill 负责协调六个子 Skill；原始日志、Case 和固件知识库是输入，Excel 是输出。

输入支持由现有解析器处理的 ASUP 归档。不要把“支持 ASUP”理解为任何格式、任何 ONTAP 版本都已经验证；缺失、损坏和不支持的来源必须保留诊断，不能填假数。

## 2. 报告效果

完整来源报告包含 25 个 Sheet，能查看控制器、节点容量、卷清单、FlexGroup、Bucket、固件、网络/EMS、Case、最佳实践及导出策略等信息。Cover/Index 便于导航。真实缺少固件日志可以省略相应固件页，其他必需内容不能静默丢失。

卷数据使用完整的集群/SVM/卷身份，不能因为跨集群同名就去重。未知与零区分显示。最佳实践保留 14 项，其中老旧快照严格超过 120 天；FlexGroup Convert 只是容量与历史趋势的评估建议，不会转换存储。

示例名称统一使用虚构的 `demo-site`，不提供真实客户截图或报告作为公开样本。需要了解具体字段时，查看对应子 Skill 的 `SKILL.md` 和源码。

## 3. 下载与试用

先取得私有仓库读取权限，下载源码压缩包并解压，或克隆仓库。在全新目录按 README 的命令安装本地候选运行环境、执行 doctor、测试、打包和 complete 场景。

这些操作只写入被忽略的 `.local`。`install` 不会把 Skill 安装到 Codex、Trae 或其他 Agent 的 Skill 根目录，也不会覆盖已有配置。运行失败应保留日志排查，不要降低测试门槛。

可进一步在不同的新输出目录执行 `missing-switch`、`broken-switch`、`identity-gap` 场景。损坏来源场景验证的是拒绝交付报告；命令测试通过不意味着它生成了一份可交付报告。

## 4. 如何接入同事自己的 Agent？

当前还没有经过新机器验收的一键通用安装流程。正式接入需确认：

1. Agent 如何识别 `SKILL.md`、如何执行 Python，是否允许本地文件访问。
2. 主 Skill、六子 Skill、共享文件和旧适配器的完整部署关系。
3. 自己的日志、知识库、历史趋势、输出目录和私有客户规则配置。
4. 依赖安装、归档解压工具和适用日志格式。
5. 用自己的脱离生产控制的测试输入核对卷覆盖、单位、容量及报告格式。

不要只把 `src/NetApp-SAM-Report` 拷进 Agent 后就认为全部模块可运行。配置模板 `config/project.example.json` 提供隔离路径示例，不包含维护者真实配置。管理入口的 report/trend 替代配置保护仍未开放为通用生产入口。

## 5. 使用边界与下一步

日常生成报告不修改源码、不自动提交或上传报告，也不改变存储配置。生产数据与输出应留在仓库外独立本地目录。

下一阶段建议：明确首批支持的 Agent，提供完整安装/卸载与依赖检查，打包全部必要运行文件，再用新机器和脱敏 ASUP 做端到端验收。此项不是本轮文档提交已经实现的功能；稳定 Release、访问权限变更和生产部署均单独审批。
