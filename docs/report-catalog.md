# 多报告 Skill 接入与管理

## 当前定位

展示名称采用 **NetApp Report Skills**，当前仓库地址与现有 SAM 文件路径保持不变。先建立清晰导航，再按实际验收结果接入更多报告，不提前重构可用功能。

| 类型 | 已有成果 | 下一步 | 不能提前宣称 |
|---|---|---|---|
| SAM | 六模块源码、分发候选包、中文指南及隔离合成验收 | 客户端 UI 和新机器试用、完善发布门槛 | 已成为所有平台认证的稳定版 |
| PA | packages/pa 独立源码、0.2.0 源码安装候选 ZIP、指标口径、合成测试、LIF/IFGRP 端口用途映射 | 同窗 AIQUM 校准、新机器与客户端实际验收 | 通用跨 Agent 已认证；SAM 包包含 PA |
| Trend | 已保留原容量等趋势源码，新增跨报告接口计划 | 审核月份、完整身份、配置变化、PA 窗口和版本兼容，独立整合和验收 | 已有容量/配置/性能统一趋势包 |

## 当前组织方式

```text
README.md                         # 三类报告的统一中文导航
docs/report-catalog.md            # 接入状态与规范
docs/pa-report.md                 # PA 独立安装与验证说明
packages/pa/                      # PA 完整源码和独立 Skill
examples/                        # 仅虚构样板及生成说明
distribution/                    # 各报告的独立安装包与精确校验文件
src/                             # 现有 SAM 源码本轮不移动
```

PA 放 packages 而非 reports，避免与客户报告输出目录的忽略规则混淆。
不移动 SAM 的 src 或生产路径，不改 SAM 安装器，不创建空的 Trend 安装包。

## 安装和版本边界

SAM 保持现有 0.5.0 项目版本及固定分发候选；PA 使用独立 VERSION（当前 0.2.0）。
每种 Skill 的安装包、校验和与验收分别记录。PA 是完整源码 ZIP，解压后运行
安装脚本注册为独立 Skill，不是当前 SAM 的 WorkBuddy 单文件导入包。
目前 PA 仅在 Windows/Codex 现有运行依赖上验收；新机器和其他 Agent 不冒称可用。

本机 SAM 与 PA 仍各有唯一受管理业务源；共享仓库为各自脱敏同步边界，
不得两处独立改同一业务。更新步骤见 PA 源码中的 docs/github-sync-plan.md。
源镜像工具会拒绝目标独立修改或隐式删除；日常报告不拉代码、不提交、不上传。

Trend 接口方向见 packages/pa/docs/trend-data-contract-plan.md。
先按完整资源身份、实际窗口、单位和指标版本定义适配器，后续再实现联合分析；
容量快照、配置时点和短窗口性能不混称整月连续数据。

## 新报告接入清单

1. 明确功能、输入格式、字段单位、版本范围、输出和失败条件；不要把 SAM 的 25 页与 14 项检查套用到 PA 或 Trend。
2. 审查业务代码、知识库依赖与原始历史；客户命名和本机路径外置，不上传真实数据。
3. 保持独立 Skill 触发条件、独立输出目录与独立安装包，不要求使用者安装不需要的报告。
4. 为每类报告提供纯虚构样板、中文安装步骤、依赖说明、单元测试及端到端验证。
5. 共享依赖仅在确有重复且完成回归后提取；不为统一目录而改坏已有功能。
6. 每个包关联对应提交、哈希、验收摘要和已知限制。源代码提交不等于正式发布，稳定 tag/Release 仍单独审批。
7. 在一个仓库管理需求和跨报告兼容；各报告独立包、版本、测试。PA 更新不改变 SAM 0.5.0，也不重打包原 SAM ZIP。合并 main、tag/Release、CI 和生产部署分别确认。

## 公开不等于已选开源许可证

仓库可公开查看与下载，但当前尚未选定 LICENSE。公共可见性本身不明确授予修改或再分发权利。许可证由维护者另行选择；接入第三方代码与依赖前核对其许可证，不代替维护者擅自选 MIT、Apache 或其他条款。
